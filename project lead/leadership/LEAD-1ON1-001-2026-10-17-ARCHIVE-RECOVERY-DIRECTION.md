# A25 Leadership One-on-One 001 — The Horse Before the Cart
DATE: 2026-10-17
PARTICIPANTS: Zed (human owner and approval authority), GPT (project lead)
STATUS: RECORDED — OWNER AGREED TO DIRECTION

## The goal
A new GPT or Claude chat should be able to retrieve the real last verified project state after a chat ends, a context limit is reached, an AI makes a mistake, or a network/server component fails. Preserve source evidence, distinct AI interpretations, failed tests, corrections, and successful checkpoints. Avoid unsupported completion claims and AI-generated filler masquerading as verified work. Build an A-to-Z repeatable project process.

## What RN-001 has demonstrated
- GPT recall reports and ID reservation delivered to GitHub.
- Claude original recall and same-chat addendum delivered to Drive without overwriting original.
- Zed relayed between separate sessions; both AI seats reported read-only observations of selected phone terminal listings, and the owner supplied screenshots.
- Claude explicitly blocked on unconfirmed ID; lead reserved ID; Claude resumed.
- A historical Gate-01 timestamp misattribution was identified and preserved as an additive correction.
- Worktree and checkpoint filenames were visible; their bytes, complete inventory and current Git HEAD were not proven by listings.
- MCP/viewport and Cloudflare logs show point-in-time operation with mixed HTTP responses and degraded transport; not continuous availability or production readiness.

## Central conclusion
Do not try to solve archives, interpretation, validation, multi-AI collaboration and server security in one build. First establish a trustworthy path to preserve, identify, verify and retrieve one piece of work. Do not depend on any model's memory alone.

## Dependency order
1. Archives: immutable original evidence and references; source provenance, dates, hashes, project/branch/component IDs. Distributed originals may stay in GitHub/Drive/approved phone storage; use an index, not one giant data dump.
2. Archivist: derived, evidence-linked project/version/test timeline; preserve original names and aliases and unresolved differences.
3. Watchdog: independently flag unsupported claims, mismatched hashes, misattributed timestamps, identity conflicts, false PASS/completion, missing proof; report rather than silently repair.
4. Roundtable and Hallways: coordinate independent AI builders/reviewers using verified references, without merging identities or letting one AI answer for Zed.
5. Pocket Server integration: automate proven exchange only behind its separate hardened security/authorization work; public read-only viewport never grants command rights.
This is dependency order, not an instruction to halt independent Pocket Server security work.

## First end-to-end proof
Use RN-001 as the pilot. Open a fresh GPT chat with no reliance on this chat's memory. Ask it to retrieve purpose, source records, passed/failed/unknown states, chronological corrections, exact stopping point and next justified action, citing sources. Repeat with Claude. Introduce controlled contradictory claim, missing file, disconnected server and interrupted session to validate Watchdog and recovery. Treat each failure as a preserved test case and each independently reproduced success as a checkpoint.

## Roles
Zed: decides priorities, approves sensitive actions, operates phone/server, owns final decisions.
GPT lead: coordinates, reconciles evidence, records state, requests decisions.
Claude and other sessions: independent build/review/test within granted scope.
Archives: preserve originals. Archivist: organize derived knowledge. Watchdog: check claims. Roundtable/Hallways: communication and coordination. Pocket Server: eventual secure transport/shared services.

## Boundaries and risks
Current RN-001 exchange is a promising controlled human-relayed workflow, not proof of fully autonomous recovery, production-safe authentication, complete device inventory or all systems connected. Keep event time, observation time and recording time separate. Preserve failed and superseded versions. Protect private files, tokens, credential paths and sensitive logs. No autonomous server operations or protected merges.

## Closing principle
We are not building an AI that never makes mistakes. We are building a workshop where mistakes cannot quietly become facts, successful work does not disappear, and a new AI can continue from the last verified checkpoint.
